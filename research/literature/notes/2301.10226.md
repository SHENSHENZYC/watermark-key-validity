## Q1 Null and what is random

Observed.
- Null (p.2): "H0 : The text sequence is generated with no knowledge of the red list rule."
- What is random (p.3): "Because the red list is chosen at random, a natural writer is expected to violate the red list rule with half of their tokens, while the watermarked model produces no violations." "The probability that a natural source produces T tokens without violating the red list rule is only 1/2T , which is vanishingly small even for short text fragments with a dozen words."
- z-test (p.3): "If the null hypothesis is true, then the number of green list tokens, denoted |s|G , has expected value T /2 and variance T /4." "Suppose we choose to reject the null hypothesis if z > 4. In this case, the probability of a false positive is 3 × 10−5 , which is the one-sided p-value corresponding to z > 4." Soft watermark (p.3): "We assume the null hypothesis (1) and compute a z-statistic using Equation (2). We reject the null hypothesis and detect the watermark if z is greater than a threshold."
- Seeding in practice (p.2): "Compute a hash of token s(t−1) , and use it to seed a random number generator." "The red list generator is seeded with the prior token s(t−1) , enabling the red list to be reproduced later without access to the entire generated sequence."
- Idealisation acknowledged (p.4): "Our analysis assumes the red list is sampled uniformly at random. This is a deviation from the method used in practice, which generates red lists using a pseudorandom number generator seeded with previous tokens. The consequences of pseudo-random sampling are explored in Section 5."
- Pseudo-randomness caveat (p.5): "A subtlety of the proposed approach is that tokens in the green list are only pseudorandom, and n-grams of text that are repeated will always be scored in the same manner."
- Expectation over the list also in the quality theorem (p.5): "The expected perplexity of the T th token with respect to the randomness of the red list"
- Claims about false positives (p.13): "The watermarking scheme we propose is designed so that false positives are statistically improbable, regardless of the writing patterns of any given human." Table 7 (p.21): "Type-I errors, false positives, are improbable by construction of the watermarking approach, but type-II errors, false negatives, appear naturally for low-entropy sequences that cannot be watermarked."

Reader's inference. The guarantee is marginal over the random green/red partition: the text is treated as fixed and arbitrary ("regardless of the writing patterns of any given human") and the randomness is the list. The paper itself flags that practice replaces the uniformly random list by a pseudo-random one seeded by context, and the only consequence it works out is repeated n-grams. In the public scheme there is no master key at all (torch RNG seeded by the previous token, p.7), so the deployed detector is a single fixed hash; the FPR the experiments measure is therefore a single-hash (key-conditional) FPR even though the derivation is marginal.

## Q2 Fixed key / per-key / key screening

Observed.
- Repetition risk and remedies (p.5): "Repetitive usage of this 2-gram would result in a higher than expected number of green tokens. In a worst-case scenario, humangenerated text with a high number of repetitions of this 2-gram may be erroneously flagged as machine-generated." "Two remedies are possible: The first is to simply increase the length h of the PRNG function, thereby increasing the variability of the green-listed words, as larger (h + 1)-grams are much less likely to be repeated." "A better remedy (possibly used in conjunction with the first) is not to count repeated n-grams when checking for the watermark." "In the example above, the 2-gram “Barack Obama” would be counted on its first occurrence, and then subsequently ignored when it appears again; it is counted as neither green nor red, and the token counter T is not incremented."
- Private key (p.6): "A watermark can also be operated in private mode, in which the algorithm uses a random key that is kept secret and hosted behind a secure API." "To create a private watermark, we first choose a random key K; a private red list for token s(t) can then be generated in a manner similar to what was described earlier"
- Multiple keys (p.7): "A straightforward add-on to significantly boost the difficulty of brute-forcing a hidden watermark scheme is to have k > 1 different hidden keys, and to randomly choose one for each generation. At detection time, we run k tests, one for each of the possible keys." "This comes at the cost of only a minor decrease in power, as we need to correct for multiple hypotheses, for example via Bonferroni correction." "When γ = .5 (half the vocabulary is colored green), lists should further be constructed so that each word is green for k/2 of the keys and red for the other k/2."
- Hash used in the experiments (p.7): "We generate red lists using the torch random number generator and one previous token as described in Section 3."
- Detector depends only on γ and the hash (p.13): "The z-statistic used to detect the watermark depends only on the green list size parameter γ and the hash function for generating green lists. There is no dependence on δ or any other factor related to how the green list is enforced."
- Threat model (p.19): "In public mode, the attacker is aware of all details of the hashing scheme and initial seed. In private mode, the attacker is aware of the watermark implementation, e.g. Algorithm 3, but has no knowledge of the key of the pseudo-random function F ."
- Variation of the FPR across keys, per-key calibration, key screening or key choice: not found (searched: key, seed, fixed, screening, Kolmogorov, uniform, "false positive", FPR, repeat, n-gram, tuple, calibrat, deployed; see "Not found").

Reader's inference. The multiple-keys proposal is the only place where several per-key tests are contemplated, and it is motivated by secrecy; the Bonferroni argument presupposes that each per-key test is itself calibrated. The repeated-n-gram remedy removes within-text dependence; it does not address a shift in the null green fraction that one hash induces across distinct n-grams of natural text.

## Q3 Empirical FPR procedure

Observed.
- Data (p.7): "we slice and dice a random selection of texts from the news-like subset of the C4 dataset (Raffel et al., 2019). For each random string, we trim a fixed length of tokens from the end and treat them as a “baseline” completion." "For the experimental runs using multinomial sampling, we pull examples from the dataset until we achieve at least 500 of generations with length T = 200 ± 5 tokens." "A larger oracle language model (OPT-2.7B) is used to compute perplexity (PPL) for the generated completions and for the human baseline."
- Error metrics (p.7): "We measure watermark strength using the rate of type-I errors (human text falsely flagged as watermarked) and type-II errors (watermarked text not detected)." (p.8): "We compute results using 500 ± 10 sequences of length T = 200 ± 5 tokens for each parameter choice."
- Result (p.8–9): "Note that no type-I (false positive) errors were observed for any run" / "shown in the error tables (see the columns of 0.0’s". Table 2 caption (p.9): "Each row is averaged over ∼ 500 generated sequences of length T = 200 ± 5. A maximum of one type-I (false positive) error was observed for any given run." Table 8 caption (p.22): "For all experiments, no false positives were observed and so FPR= 0 and TPR= 1." [sic in the PDF; presumably TNR = 1]
- Nominal level (p.5): "We also assume a detection threshold of z = 4 (which occurs at ∼ 128.2/100 tokens) which gives us a type-I error (false positive) rate of 3 × 10−5 ."
- Pointer to theory comparison (p.8): "We further report detection performance and error rates for various cutoffs in Appendix C, and provide a comparison between empirical z-scores and theoretical predictions." Observed: Appendix C's Fig. 7 (p.22) compares the empirical green-list fraction under the watermark with the Theorem 4.2 bound; it is not an empirical-versus-theoretical FPR comparison.

Reader's inference. One hash (torch RNG seeded by the previous token; no master key), about 500 human baseline completions from C4 news-like at T about 200 per run, and an observed FPR of 0.0 (at most one false positive in about 500) at z = 4 and z = 5. This is consistent with, but cannot test, the nominal 3e-5 level: a 500-text null resolves nothing below roughly 2e-3. There is no per-key analysis and no explicit empirical-versus-nominal FPR check in this paper; that check first appears in 2306.04634 (Appendix A.3) and 2308.00113.

## Q4 Remedies

Observed.
- Skipping repeated n-grams (p.5), with a sensitivity bonus: "In addition to preventing false positives, skipping repeated n-grams can also make the detector more sensitive. A repeated n-gram is likely to be low-entropy, and so it will not contribute to the strength of the watermark."
- Increasing h (p.5), against attack amplification (p.6): "To limit amplification, we suggest using a small window (h = 2 or 3) when using the naive watermarking rule."
- Algorithm 3, robust private watermarking with self-hashing (p.7).
- Multiple keys with a Bonferroni correction (p.7; quoted in Q2).
- Multiple watermarks (p.20): "Multiple Watermarks. A company might also apply multiple watermarks to generated text, taking the union of all red lists at each token."
- Input canonicalisation (p.10): "Security against Homoglyph and tokenization attacks can be maintained using input normalization before the text is tested for watermarks, for example via canonicalization as in Helfrich & Neff (2012)."

Reader's inference. Every remedy is either dependence removal, a security measure, or a multiplicity correction; none calibrates the test to the deployed hash, and none comes with evidence beyond the 500-text tables.

## Reader's inference

1. Guarantee type: marginal over a uniformly random red list; the paper says so and flags the pseudo-random practice as a deviation whose only analysed consequence is repeated n-grams.
2. Per-key dispersion: absent as a concept; in public mode the hash is fixed and keyless, so the experiments measure one fixed-hash FPR with about 500 nulls (observed 0 or 1 false positives), which cannot test the nominal 3e-5.
3. The multiple-keys idea with Bonferroni is the seed of later multi-key schemes but assumes each key's test is already valid.
4. The "regardless of the writing patterns of any given human" claim (p.13) is a statement about the marginal test; nothing in the paper supports it for a particular fixed hash.
