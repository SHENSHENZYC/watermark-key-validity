# C03 — Anytime-valid sequential LLM evaluation (search-level screen, 2026-10-08)

## Candidate (one sentence)
Can confidence sequences and e-processes for paired differences and win rates (Waudby-Smith–Ramdas betting confidence sequences; Howard et al. time-uniform bounds) let an evaluator stop an LLM evaluation early with valid error control, and how much does that save against fixed-n evaluation on real benchmark streams under item heterogeneity and ordering effects?

## Occupied (what the candidate can no longer claim)
- "Anytime-valid confidence sequences / e-processes for LLM evaluation with early stopping" as a contribution: taken for single-model scores (CELEUS; Hsu & Shekhar), for pairwise preference ranking (SERPANT, ICML 2026), for shared-item leaderboards (Rank CS; BB-EDGE) and for paired policy comparisons on replayed traces (Deadline-Valid Replay).
- Savings claims: CELEUS reports 54–62% fewer samples; SERPANT claims substantial annotation savings; the anytime penalty (≈2× N* in one paired setting) is already reported.
- Efficient fixed-budget evaluation via IRT (tinyBenchmarks and successors) occupies the adjacent "adaptive testing" route.

## Residual gap (type: adequacy check)
Observed: none of the retrieved abstracts studies how the stated guarantees and stopping times behave when a *fixed* benchmark is replayed in its native order (items clustered by subject or difficulty) rather than uniformly at random, nor compares betting, empirical-Bernstein, Bayes-assisted and sampling-without-replacement constructions head-to-head for the paired Bernoulli difference on the same public per-item records — "search-level; absence is not proof of novelty"; the queries that returned nothing on ordering/heterogeneity were the arXiv API `abs:"early stopping" …` and `abs:"always valid" …` sweeps and the three OpenAlex sweeps.
Inference: for a fixed finite benchmark the natural target is the fixed-set paired difference, for which without-replacement confidence sequences apply only if the replay order is randomised; under native ordering the running-mean target drifts and standard constructions can fail, which is a known caveat rather than a new finding. The comparative adequacy question is small and several groups with released code are positioned to answer it quickly.
Proposal: if pursued, restrict to an adequacy report on public per-item records (Open LLM Leaderboard v2 samples; MMLU-Pro subject order) measuring stopping-time savings and empirical error of four constructions under random vs native ordering, with CELEUS/BB-EDGE/Rank-CS as comparators; otherwise fold the anytime-valid angle into C01 or C02 as a robustness arm.
